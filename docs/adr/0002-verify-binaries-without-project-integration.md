# Verify loaded binaries without project integration

RWL defines launch success as proof that the launched Rhino process is using the expected `.rhp` from its exact selected-worktree artifact path. Launched plug-ins are not required to expose authentication, initialization, callback, or receipt-writing behavior; this deliberately trades plug-in-specific readiness guarantees for a zero-integration, low-friction project boundary. ADR 0010 changes artifact ownership without changing this verification rule.

Amended 2026-08-15: proof is produced by external file-use attribution, not by a bundled in-Rhino verifier plug-in. A loaded assembly is a file mapped into the Rhino process's address space, so RWL enumerates the launched PID's mapped files and requires the selected `.rhp` path among them. The earlier bundled `Rwl.RhinoVerifier.rhp` never produced a verification on any machine (an in-process verifier must itself be loaded, recreating the problem it was meant to solve) and was removed. Critical dependencies are existence-checked beside the plug-in during prepare but are not load-gated: lazily-loaded dependencies (for example solvers) are legitimately unmapped at startup, so a startup load gate on them can never pass. The Restart Manager cannot serve as the attribution primitive because mapped managed assemblies hold no open handle and no loader-table entry.
